# 무고 — 誣告 · 無辜

안개 낀 항구 마을 회항. 연쇄살인 용의자를 심문하고, 당신의 한마디로 그 사람의 생사가 갈린다.

**당신이 심문하는 남자는 이 게임을 먼저 한 사람이다.** 그가 화면에 쓴 세 마디가 그대로
당신 앞에 놓이고, 당신이 「유죄」를 누르면 그 사람의 메일함으로 사형 통지가 간다.
그리고 그날 밤, 같은 일이 당신에게 일어난다.

한 판 20~30분. 한 사람이 한 번씩 심문하고, 한 번씩 심문당한다.

## 실행

```bash
npm install     # 최초 1회
npm start       # http://localhost:8787
npm test        # 저장소·API 왕복 검사
```

## 이어달리기가 성립하려면

이 게임의 전부는 **내 진술이 다음 사람에게 넘어가고, 며칠 뒤 판결이 메일로 오는 것**이다.
그러려면 서버와 데이터베이스가 있어야 한다. GitHub Pages 같은 정적 호스팅으로는 안 된다.

| | 되는 것 | 안 되는 것 |
|---|---|---|
| 정적 호스팅 | 혼자 처음부터 끝까지 플레이 | 이어달리기 전부. 미리 써둔 조서만 나옴 |
| 서버만 (DB 없음) | 서버가 깨어 있는 동안은 이어달리기 | 재배포·재시작하면 대기 중인 진술이 전부 사라짐 |
| 서버 + Postgres | 전부 | — |
| ＋ SMTP | 판결이 메일로 도착 | — |

### 환경변수

다 없어도 게임은 돌아간다. 없는 만큼만 기능이 빠진다.

| 변수 | 없으면 | 예시 |
|---|---|---|
| `DATABASE_URL` | `data/statements.json` 파일에 저장 (재시작하면 날아감) | `postgres://…` (Neon·Supabase 무료 등급) |
| `BREVO_API_KEY` | 아래로 넘어간다 | `xkeysib-…` ([brevo.com](https://brevo.com) 무료 하루 300통) |
| `RESEND_API_KEY` | 아래로 넘어간다 | `re_…` ([resend.com](https://resend.com) — **도메인 필요**, 아래 참고) |
| `SMTP_URL` | 메일을 콘솔에만 찍음. 조서 번호 링크로는 확인 가능 | `smtps://아이디@gmail.com:앱비밀번호@smtp.gmail.com:465` |
| `MAIL_FROM` | `회항 경찰서 <no-reply@localhost>` | `회항 경찰서 <아이디@gmail.com>` |
| `PUBLIC_URL` | `http://localhost:8787` | `https://mug0.onrender.com` |

메일 경로는 `BREVO_API_KEY` → `RESEND_API_KEY` → `SMTP_URL` → 콘솔 순으로 있는 것을 쓴다.

**도메인이 없으면 Brevo 를 쓴다.** Resend 는 도메인을 인증하기 전까지 `onboarding@resend.dev`
로 **자기 계정 주소에만** 보낼 수 있어서, 모르는 사람에게 판결이 가야 하는 이 게임에는 못 쓴다.
Brevo 는 발신자 주소 하나만 인증하면(gmail 주소도 된다) 아무에게나 보낼 수 있다.
`MAIL_FROM` 의 주소가 그 인증된 주소와 같아야 한다.

Gmail SMTP 는 2단계 인증을 켠 뒤 **앱 비밀번호**를 발급받아 쓴다. 계정 비밀번호로는 안 된다.

`PUBLIC_URL` 은 판결 메일 안의 링크에 그대로 박힌다. 실제 도메인과 한 글자라도 다르면
받은 사람은 죽은 링크를 받는다. 배포 후 반드시 눈으로 맞춰볼 것.

### Render 배포

`render.yaml` 이 들어 있다. Render 대시보드에서 이 저장소를 연결하면 그대로 뜬다.
위 변수들은 대시보드 → Environment 에 직접 넣는다 (`render.yaml` 에는 비밀을 적지 않는다).

**무료 플랜에서는 SMTP 가 안 된다.** Render 는 2025-09-26 부터 무료 웹 서비스의
아웃바운드 25·465·587 포트를 전부 막는다. `SMTP_URL` 을 넣어도 `Connection timeout`
으로 죽는다 — 앱 비밀번호가 틀린 게 아니다. 포트를 안 타는 `BREVO_API_KEY` 를 쓰거나,
유료 인스턴스로 올려야 한다.

무료 등급은 15분 놀면 잠들고, 첫 접속에 30초쯤 걸린다. 파일 시스템은 재배포 때마다 지워지므로
`DATABASE_URL` 을 반드시 붙여야 대기열이 유지된다.

### 밀린 통지 다시 보내기

발송이 실패하면 주소를 지우지 않고 남겨둔다. 나중에 경로를 고친 뒤 밀린 것을 한 번에 보낼 수 있다.

```
DATABASE_URL=… BREVO_API_KEY=… node tools/resend.js          # 누가 밀렸는지 본다
DATABASE_URL=… BREVO_API_KEY=… node tools/resend.js --send   # 실제로 보낸다
```

## 조서를 누구에게 주는가

지어낸 조서(`seeds.js`)를 주면 그 판은 아무와도 안 엮인다. 그래서 사람이 쓴 것을 늘 먼저 준다.

1. **아직 판결 안 난 진술** — 잠금을 걸고 하나씩. 둘 이상 쌓여 있으면 서로 다른 것을 받는다
2. 그게 없으면 **이미 판결이 난 진술을 한 번 더** — 한 조서는 두 사람까지 읽는다.
   자기 진술과 자기가 이미 판결한 조서는 걸러진다
3. 둘 다 없을 때만 **지어낸 조서**

두 사람이 반대로 읽어도 그대로 둔다. 회항에는 그 둘을 맞춰줄 사람이 없다 —
판결 두 개가 나란히 남고, 통지도 두 번 간다.

## 개인정보

메일 주소는 **판결 통지를 보내는 데만** 쓴다. 한 조서에 통지는 많아야 두 통이고,
마지막 한 통이 실제로 나간 다음에 DB에서 지운다 (`store.clearEmail`).
발송에 실패하면 남겨둔다 — 지워버리면 다시 보낼 길이 없다(`tools/resend.js`).
주소를 안 대도 플레이는 끝까지 되고, 조서 번호(`/?t=…`)로 직접 판결을 확인할 수 있다.

## 구조

```
server.js     HTTP + 정적 파일. 하는 일은 셋뿐 — 진술 꺼내주기 / 판결 받기 / 진술 넣기
store.js      Postgres 또는 JSON 파일. 같은 인터페이스
mailer.js     판결 통지. Brevo → Resend → SMTP → 콘솔 순으로 있는 길을 쓴다
seeds.js      사람이 쓴 조서가 하나도 없을 때만 내놓는 조서 10개
public/
  story.js    대본 전부. 글자만 들어 있다
  plates.js   관찰 장면의 사진·그림과 단서 좌표
  img/        관찰 장면 사진 (전부 퍼블릭 도메인 — CREDITS.md)
  game.js     진행부
tools/
  storymap.js 대본에서 분기도(HTML)를 뽑는다 — node tools/storymap.js
  queue.js    누가 판결을 기다리는지 들여다본다
  resend.js   못 나간 판결 통지를 다시 보낸다
```

### 사람 사이로 넘어가는 것

* **세 마디** — 제9장에서 내가 쓴 답 → 다음 사람의 제2장 심문 화면
* **찢긴 자리** — 제8장에서 내가 수첩에서 찢어낸 장 → 다음 사람에게 「계획적이었다」는 결론으로만
* **판결** — 제2장에서 내가 내린 한마디 → 앞사람의 메일함. 그 조서를 읽는 사람은 나 말고 하나 더 있을 수 있다

## API

| | |
|---|---|
| `POST /api/case` | 앞사람의 진술을 하나 꺼내 잠근다 (30분 뒤 자동 해제). 미판결이 없으면 판결된 것을 한 번 더 |
| `POST /api/verdict` | 판결을 기록하고 앞사람에게 메일을 보낸다. 한 조서에 두 번까지 |
| `POST /api/statement` | 내 진술을 대기열에 넣고 조서 번호를 준다 |
| `GET /api/statement/:token` | 내 판결이 나왔는지 확인 |
| `GET /healthz` | 상태 |
